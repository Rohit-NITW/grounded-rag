# Northstar Engineering — Developer Onboarding

This is fictional sample documentation for a software portfolio demonstration.

## First day

New engineers receive a development laptop and a password manager account on their first day. Enable full-disk encryption and automatic operating-system updates before accessing company repositories. Complete multi-factor authentication enrollment for the source hosting platform, cloud console, and VPN. The onboarding buddy checks that all required accounts are active.

## Development environment

Use Python 3.12 and Node.js 22 for the sample product. Local services run through Docker Compose. Copy the example environment file and request development secrets from the team secret manager. Never copy production data into a laptop database. Use the anonymized seed dataset maintained in the development repository. A successful setup includes running the test suite and sending one request to the local health endpoint.

## First change

The first pull request should be a small documentation or test improvement. Every pull request must describe the problem, the implementation, and the validation performed. At least one peer reviewer must approve before merging. The author should be ready to explain any generated code and the tests that verify its behavior. Screenshots are required for visible interface changes.

## Learning and support

Each new engineer has an onboarding buddy for the first thirty days. The buddy schedules two check-ins per week during the first month. Access problems should be reported in the internal helpdesk with the failing service name and a sanitized error message. The team lead reviews the onboarding checklist at the end of week one and assigns a scoped starter project for the following sprint.
